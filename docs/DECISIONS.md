# Decisions

| ID | Decision | Reason |
| --- | --- | --- |
| D-01 | Deleted the pre-existing tycoon template (`src/**` old scripts, DataStore code, gamepass handlers). It remains in git history. | User chose option A. It violated ARCH-06 (no DataStores) and the 3.3 layout. |
| D-02 | `AugmentCategory` stays `"Economy" \| "Combat" \| "Items"` (no `"Hybrid"`); a hybrid is an augment with two categories. | 10.1 describes Hybrid as two categories on one augment; 13.1 type has no Hybrid. |
| D-03 | Added optional fields to `AbilityEffect`: `stat` (which stat a StatBuff changes), `onSelf` (apply to caster), `options` (pick one effect list via combat RNG). | 13.1 cannot express Pocket Pharaoh's self armor, Pixel Pup's buff, or Lootbox Lemur's roll. Schema change per 13. |
| D-04 | Ability data conventions: `effect.radius` with `CurrentTarget` splashes around the target; Slow/StatBuff `values` are whole percents; Mana `values` are signed amounts. Trait/item/augment params use fractions (0.02 = 2%). | Doc silent; simplest consistent choice. |
| D-05 | Tests use a hand-written plain-assert runner (`tests/Runner.luau`), run from Studio's command bar. No TestEZ, no lune. | 1.2 rule 4 forbids unlisted dependencies; user did not request lune. Terminal test runs are therefore not available. |
| D-06 | `tests/` maps to `ServerScriptService/Tests` in `default.project.json`. | 3.3 only lists `tests/`; tests need to require Shared and Server. |
| D-07 | `BaseStats` lives in `Shared/Util` (not `Server/Combat`). | The client unit info card (12.2) needs the same resolved stats. |
| D-08 | `Damage` requires configs through `ReplicatedStorage.Shared` by service path; it still touches no gameplay Instances (ARCH-04). | Server and Shared live in different services, so a relative require is impossible. |
| D-09 | Damage floor (1) is applied after mitigation and reductions, before shields. | 11.4 step 7 lists the minimum last, but shields (step 6) would otherwise absorb a sub-1 amount. |
| D-10 | The Effect-module existence check from 13.4 is a skipped test marked `TODO(phase 5)`. | Effect modules are Phase 5 and 6 deliverables. |
| D-11 | Augment rarity weights (10.3) live in `GameConfig.augmentRarityWeights`. | They are `[CONFIG]` values. |
| D-12 | `wonLastPvp` is true only if the round just finished was a PvP win; a PvE, carousel or draw round clears it (streak length is untouched). | 5.2 says "won the previous PvP round" but worked example C says a PvE last round gives 0 win bonus. |
| D-13 | Unit and item uids are numbers from one per-player counter. A unit's items are derived from `inventory[*].equippedTo`, not stored on the unit. | One source of truth, so merge/sell cannot desync items. |
| D-14 | Shop fallback (SHOP-05) only goes to lower tiers; an exhausted tier 1 yields an empty slot. | Literal reading of 6.4. |
| D-15 | `PlayerState.moveUnit` (BRD-03, BRD-04) is implemented in Phase 2 so board-cap rules are testable; ActionRouter will add phase and ownership checks in Phase 3. | Pure logic, tiny, needed by merge tests. |
| D-16 | Added `Shared/Util/Index` (unit/item id lookup) and `PlayerState` helpers beyond the listed files. | Avoids duplicating lookups in every service. |
| D-17 | Lobby start rule: the match starts when the lobby is full, or after `lobbyWaitSeconds` (10s) with at least `minPlayersToStart` (1) players. Empty seats stay empty until bots arrive in Phase 8. A 3-second `MatchStart` phase precedes round 1-1. All three are `[CONFIG]` in `GameConfig`. | Doc defines the Lobby/MatchStart states but not when they end; solo play must work for the Phase 3 acceptance test. |
| D-18 | A match started with one player never ends by "last player standing" (the end check only fires at 0 living). A lone player's PvP round is a ghost fight against a copy of their own board. | Needed so the solo Phase 3 test can run past round 2-3; PAIR-02 only covers odd counts of 2 or more. |
| D-19 | `PlaceholderCombat` decides fights by board strength until `CombatSim` exists; marked `TODO(phase 4)` and injected through `deps.combat`. PvE drops and income modifiers are injected the same way (`onPveDrop`, `incomeModifiers`), marked for phases 6 and 5. | Phase 3 needs Combat/Resolve to run, but the sim is Phase 4 and inventory is Phase 6. |
| D-20 | `MatchService` is driven by `update()` with an injected clock. Each transition is scheduled from the previous phase's deadline, not from "now". | Makes the state machine testable with a fake clock (ARCH-05) and prevents drift. |
| D-21 | Added `Player/Snapshot`, `Player/Replicator`, `Match/RoundResolver`, `Match/PlaceholderCombat` and `client/StateStore` beyond the 3.3 file list. Remotes are created in code by `Main.server`. | Keeps MatchService under 400 lines and keeps all Remote firing in one adapter. |
| D-22 | Item, augment and carousel actions (`EquipItem`, `UnequipItem`, `CombineItems`, `PickAugment`, `RerollAugment`, `PickCarousel`) are recognized by `ActionRouter` and rejected with `NotAvailable` until Phase 6. | 3.5 lists them as valid actions; their services do not exist yet. |
| D-23 | Rejections also raise a `Toast` remote with the reason code; `UnknownUnit` is used for both "no such unit" and "not yours" because units are looked up only in the caller's own state. | UI-05; ownership cannot be spoofed by design. |
| D-24 | The Remotes folder is named `BattlersNet` (3.5 names the remotes, not the folder). | A place file saved before the template was deleted still contains an old `ReplicatedStorage.Remotes` folder; the client waited on it forever. |
| D-25 | Summoned tokens never keep a team in the fight and are not counted as surviving units; a team with only tokens left has lost. | 11.2 step 5 says "no living units"; 4.5 counts "living units" for damage. Tokens do not count toward the board (LVL-01) so they should not decide fights either. |
| D-26 | The whole sim runs at Combat start and is played back from recorded events (`CombatPlayback`). Phase length = sim seconds (including overtime, capped by `hardCapSeconds` 90). | MatchService must know when Combat ends. Measured cost is printed by the fast-forward test; if per-fight cost is too high for a single frame we will move to incremental stepping. **Resolved:** measured 2.7 ms per fight, 0.010 ms per tick (budget 2 ms), so precomputing is fine. |
| D-27 | Added optional `AbilityEffect.behind` (Dash lands on the far side of the target; Lag Lizard). Added `adRatio` to the Training Pup summon (token AD = 25% of the summoner's AD). | 7.6 gives the pup only Health. |
| D-28 | Ability conventions: `RandomEnemies` picks distinct enemies first, then random repeats if the count exceeds the enemies alive. Cast targets are chosen at cast start; if all die during the 0.5s cast the cast does nothing. `Silence`d units that are full on mana keep it. A Dash to an adjacent target does nothing unless `behind`. | 11 and 7.6 are silent on these. |
| D-29 | Lootbox Lemur's Mystery Box is a Custom effect carrying `options`; Rotzilla's Rot stacks are stored in `unit.counters.rot` until the Brainrot trait module exists (`TODO(phase 5)`). Admin command numbers live in `CombatConfig.adminCommands`. | Section 8.3 lists commands but not their tuning as tier params. |
| D-30 | `PlaceholderCombat` is deleted. `MatchService` now requires `deps.combat`; tests inject a fixed 5-second fight so the schedule test stays exact. | Phase 4 replaces the stand-in. |
| D-31 | `Types.EffectContext` was rewritten to the shape EffectRunner actually provides: explicit-unit helpers (`addModifier(unit, stat, kind, value, duration?, subId?)`, `removeModifiers`, `queueDamage(source, target, ...)`, `heal`, `applyStatus`, `summon`), plus `members`, `units`, `params`, `state`. Every modifier a context adds is logged so `detach` can remove them all. | The 13.2 sketch used per-owner helpers that cannot express team-scope traits. Schema change per 13. |
| D-32 | Noob growth is stored on the player-state unit (`unit.growth`) and applied as static modifiers by `CombatRunner`, so it persists when the trait tier drops. When copies merge, the merged unit keeps the growth of the best-grown copy. | 8.3 says "permanently ... for the rest of the match" but does not cover merging. |
| D-33 | Items resolve in two parts: plain stat bonuses (a generic stats module per copy, ITM-04) and one effect module per distinct combined item per unit (ITM-05). Items attach before traits; every unit then starts the fight at full (bonus-included) Health. | Keeps stacking rules in one place. |
| D-34 | Generic sim mechanisms added so effects need no id checks (ARCH-03): separate `autoReduction` and `abilityReduction` stats (each positive flat modifier is its own multiplicative source, 11.4 step 5), `counters.negateAbility` charges (Spell Sponge), `counters.abilityCrit` (Mega Wand), `counters.randomTarget` (Full Rot), `sim:heal`, and revive events. | 11.4 and 9.4 need conditional reductions and a damage cancel; no id branches in the combat loop. |
| D-35 | "Cells between" for Camper means distance minus 1 (adjacent = 0), so a 4-range Marksman with +1 Range reaches exactly the 4-cell cap. Obby "respawn" revives the unit at once at its start cell but keeps it untargetable and stunned for 2s. Bouncer taunt and Rizzler charm are applied once, at combat start. Pets use the summoning member as owner. | 8.3 is silent on timing details. |
| D-36 | Fights end the sim's effect lifetime: EffectRunner detaches every effect on OnCombatEnd, so modifiers (e.g. a Speedrunner kill buff) vanish when the fight is decided. | 13.2: detach MUST remove everything a source added. |
| D-37 | `EffectModule` gained an optional `onPick(ctx)` for augments: instant gold, items and per-player Config overrides (`state.overrides`) run once when the augment is picked; combat effects use `attach` and hooks like traits do. Player-level hooks (`OnPrepStart`, `OnIncomeCalc`, `OnUnitBought`, `OnItemCombined`, `OnRoundEnd`) now fire on active traits and owned augments through `EffectRunner.firePlayerHook`. | AUG-07 asks for effects that grant gold or items and change Config for one player; 13.2's attach/detach alone cannot express a one-shot. |
| D-38 | AUG-01 puts the augment offer before the shop refresh while 4.3 lists it after; I deal it before (AUG-01 is the rule ID). The offer is only a pending choice, so the shop outcome is unchanged. | The two sections disagree. |
| D-39 | Component Coupon and Anvil Delivery open a follow-up choice (`state.augmentOffer.kind` is `component` or `combined`) that the player resolves with `PickAugment`; it has no reroll, and the end-of-Prep auto-pick takes the first option. | The GDD says "choose" but defines no UI action for it. |
| D-40 | `onPveDrop` is now called on every PvE win with the round's base drop count (0 for 1-1); `InventoryService.pveDrop` adds the PvE Bounty extra. ITM-11's no-three-in-a-row rule applies to every random component grant (drops, Starter Pack, Triple Threat) but not to the carousel. | "Every PvE round" in Bounty includes 1-1, which drops nothing by default. |
| D-41 | Winner's Purse needs a loss payout, so EconomyService tracks `lostLastPvp` and reads a `lossBonus` override (default 0); the income breakdown's `win` field carries whichever applies. Reroll Frenzy uses `state.rerollsThisRound`, reset each Prep. | 5.2 has no loss bonus; the augment adds one. |
| D-42 | Carousel pick timing: an early pick restarts the next player's 4s clock, so a carousel may finish earlier than its fixed phase length (3s + 4s x players); the phase still lasts the full time. Equipping needs a loose item (unequip first to move it); combining works on loose components only. Bots will pick instantly in Phase 8. | CAR-05 gives the length; ITM-02/03 do not say whether equipped items can be moved or fused. |
| D-43 | Frontline Frenzy's "front two rows" are rows 3 and 4 of the owner's own board (arena rows 5 and 6 for the away team). Team Spirit counts active traits (tier reached) on the side's board. Hot Streak uses the player's streak length at combat start. | 10.4 does not define "front" or when streaks are read. |
| D-44 | The combat overlay is a 2D arena view inside the UI, flipped 180 degrees when the local player is the away team, instead of moving the 3D camera to the home plot. The server still plays the fight back on 3D placeholder blocks in `workspace.Arenas` (unused by the HUD). | PAIR-03 says the away camera moves to the home plot; a flipped 2D view keeps the player's own units at the bottom and works the same on phones. **Deviation from PAIR-03 - please confirm.** |
| D-45 | The End screen panel is built in Phase 7 (12.2 lists it with the other panels); 14.1 also lists "the end screen" under Phase 8. Its Play Again button calls `TeleportService:Teleport(game.PlaceId)` with no server logic and only works in a published game. | The two sections overlap; there is no server action for restarting a match in the GDD. **Please confirm Play Again behaviour.** |
| D-46 | Layout is designed on a 1920 x 1080 reference, scaled with one `UIScale` of min(width/1920, height/1080); the root frame grows on the longer axis and side panels anchor to the edges. Landscape only. Tap targets are 44+ reference pixels as UI-03 states, but on a 812 x 375 phone the scale is about 0.35, so physical targets are small. | UI-03 is written in reference pixels; a larger minimum may be wanted after playing on a real device. |
| D-47 | Tap rules: tapping a unit selects it and opens its card (tapping it again deselects); with a unit selected, tapping any cell, bench slot or another unit moves or swaps it; with an item selected, tapping a unit equips it. Dragging works for units, items and equipped items on the same targets. The unit card covers the trait panel while open. | 12.3 gives the tap-only alternatives but not how they interact. |
| D-48 | Server additions for the HUD: `Snapshot.income` (the itemized income of the latest Prep), `mana` on Attack and Damage events and `maxMana` in the combat roster, and a 2-second snapshot heartbeat per player so a late-connecting client always catches up. The client also reads phase, round and timer from the snapshot. | The popup, mana bars and late joins need data the Phase 3 and 4 payloads did not carry. |
| D-49 | Sounds use built-in `rbxasset://` content under `Assets.sounds` (merge, traitTier, levelUp, augmentPick, combatStart, buy, toast); missing files play nothing. Banners are the on-screen effect for each. | 12.4 allows placeholders as long as they live in Assets. |
| D-50 | Bots (negative user ids) are added to every empty seat when the match starts (`GameConfig.fillWithBots`), so a one-human dev match now has bot opponents instead of a ghost of yourself. Bots read their own state and send intents through `ActionRouter` once per update (0.1s live), so the 20-per-second limit applies to them. | BOT-01, BOT-02. The solo-ghost behaviour of D-18 still applies if `fillWithBots` is false. |
| D-51 | Bot behaviour is exactly BOT-03 plus two things it needs to keep a match moving: it takes the first choice of an augment offer and picks the first free carousel item the moment it is its turn (CAR-03 says bots pick instantly). A bot board-swaps a stronger bench unit for its weakest board unit when the board is full. Bots do not equip or combine items, sell, reroll or lock. | BOT-03 says "simple"; items for bots are logged in docs/SUGGESTIONS.md. |
| D-52 | Only fights that include a human are recorded and played back in 3D; bot-vs-bot fights are simulated only. | Saves work on the server; nobody can watch them. |
| D-53 | The balance harness's "win rate by trait" counts, for each trait, the final fought boards where it was active and how many of those players placed 1st (also top 4). An even trait wins 12.5% with 8 players. | 14.1 asks for the average win rate by trait without defining it. |
